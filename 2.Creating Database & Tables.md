# 2. Creating Database & Tables

## Learning Objectives

After completing this module, you should be able to:

- Create, list, select, and delete databases.
- Create and inspect tables in MySQL.
- Delete or empty tables safely.
- Modify an existing table using `ALTER TABLE`.
- Add, modify, rename, and drop columns.
- Rename a table.
- Recognize commands that can permanently remove data.

> **Warning:** `DROP DATABASE`, `DROP TABLE`, and `TRUNCATE TABLE` can permanently remove data. Always check the database and table name before running them, and take a backup when working with important data.

---

# Part 1: Database Commands

## 1. `CREATE DATABASE`

The `CREATE DATABASE` command creates a new database.

### Syntax

```sql
CREATE DATABASE database_name;
```

### Example

```sql
CREATE DATABASE school_db;
```

This creates a database named `school_db`.

### Avoiding an Error if the Database Already Exists

If the database may already exist, use `IF NOT EXISTS`:

```sql
CREATE DATABASE IF NOT EXISTS school_db;
```

If `school_db` already exists, MySQL does not create a second copy and usually produces only a warning.

### Creating a Database with Character Settings

A character set controls how text is stored. A collation controls how text is compared and sorted.

```sql
CREATE DATABASE school_db
    CHARACTER SET utf8mb4
    COLLATE utf8mb4_unicode_ci;
```

`utf8mb4` is commonly chosen because it supports a wide range of Unicode characters.

### Important Points

- A database is a container for tables and other database objects.
- Creating a database does not automatically create tables.
- Database names should be meaningful and consistent.
- Avoid spaces and confusing special characters in database names.

---

## 2. `SHOW DATABASES`

The `SHOW DATABASES` command lists databases that the current MySQL user is allowed to see.

### Syntax

```sql
SHOW DATABASES;
```

### Example

```sql
SHOW DATABASES;
```

The result may include system databases and databases created by users:

```text
information_schema
mysql
performance_schema
school_db
sys
```

### Searching for Databases by Pattern

You can use `LIKE` to filter the results:

```sql
SHOW DATABASES LIKE 'school%';
```

This displays databases whose names begin with `school`.

### Important Points

- The command does not necessarily show every database on the server.
- Visibility depends on the privileges of the current user.
- System databases are used internally by MySQL.

---

## 3. `USE`

The `USE` command selects the database for the current MySQL session.

### Syntax

```sql
USE database_name;
```

### Example

```sql
USE school_db;
```

After this command, table commands without a database prefix apply to `school_db`.

### Checking the Selected Database

```sql
SELECT DATABASE();
```

If a database is selected, MySQL returns its name. If no database is selected, the result is `NULL`.

### Using a Database Without Selecting It

You can qualify an object with its database name:

```sql
SELECT *
FROM school_db.students;
```

The format is:

```text
database_name.table_name
```

### Common Error

If you try to create or access a table without selecting a database, MySQL may display:

```text
No database selected
```

Run `USE school_db;` before working with unqualified table names.

---

## 4. `DROP DATABASE`

The `DROP DATABASE` command permanently deletes a database, including all tables and data inside it.

### Syntax

```sql
DROP DATABASE database_name;
```

### Example

```sql
DROP DATABASE school_db;
```

This removes the entire `school_db` database.

### Avoiding an Error if the Database Does Not Exist

```sql
DROP DATABASE IF EXISTS school_db;
```

This tells MySQL to drop the database only if it exists.

### Important Warning

`DROP DATABASE` removes:

- The database itself
- Every table inside the database
- All rows in those tables
- Other objects stored in the database

Use this command only when you are certain that the database is no longer needed.

# Part 2: Table Commands

Before creating a table, select a database:

```sql
CREATE DATABASE IF NOT EXISTS school_db;
USE school_db;
```

## 5. `CREATE TABLE`

The `CREATE TABLE` command creates a new table and defines its columns, data types, and constraints.

### Basic Syntax

```sql
CREATE TABLE table_name (
    column1 data_type,
    column2 data_type,
    column3 data_type
);
```

### Example

```sql
CREATE TABLE students (
    student_id INT PRIMARY KEY,
    student_name VARCHAR(100) NOT NULL,
    email VARCHAR(150) UNIQUE,
    age INT,
    admission_date DATE
);
```

### Explanation of the Example

- `students` is the table name.
- `student_id` is an integer column.
- `PRIMARY KEY` uniquely identifies each student.
- `student_name` stores text up to 100 characters.
- `NOT NULL` requires a student name.
- `email` must be unique when a value is provided.
- `age` stores an integer.
- `admission_date` stores a date.

### Creating a Table Only if It Does Not Exist

```sql
CREATE TABLE IF NOT EXISTS students (
    student_id INT PRIMARY KEY,
    student_name VARCHAR(100) NOT NULL
);
```

### Common MySQL Data Types

| Data Type | Use | Example |
|---|---|---|
| `INT` | Whole numbers | `25` |
| `DECIMAL(10,2)` | Exact decimal values | `1250.50` |
| `VARCHAR(100)` | Variable-length text | `'Asha'` |
| `CHAR(2)` | Fixed-length text | `'IN'` |
| `TEXT` | Long text | A description |
| `DATE` | Calendar date | `'2026-09-09'` |
| `DATETIME` | Date and time | `'2026-09-09 10:30:00'` |
| `BOOLEAN` | True or false value | `TRUE` |

### Common Constraints

- **`PRIMARY KEY`:** Uniquely identifies each row.
- **`NOT NULL`:** Prevents a column from containing `NULL`.
- **`UNIQUE`:** Prevents duplicate values in a column or column group.
- **`DEFAULT`:** Supplies a value when one is not provided.
- **`CHECK`:** Enforces a condition on values.
- **`FOREIGN KEY`:** Connects a column to a key in another table.

### Example with Constraints

```sql
CREATE TABLE courses (
    course_id INT PRIMARY KEY,
    course_name VARCHAR(100) NOT NULL,
    credits INT DEFAULT 3,
    fee DECIMAL(10, 2) CHECK (fee >= 0)
);
```

### Example with Auto-Increment

```sql
CREATE TABLE teachers (
    teacher_id INT PRIMARY KEY AUTO_INCREMENT,
    teacher_name VARCHAR(100) NOT NULL,
    email VARCHAR(150) UNIQUE
);
```

With `AUTO_INCREMENT`, MySQL can generate a new numeric ID when a row is inserted without specifying the ID.

## 6. `SHOW TABLES`

The `SHOW TABLES` command lists tables in the currently selected database.

### Syntax

```sql
SHOW TABLES;
```

### Example

```sql
USE school_db;
SHOW TABLES;
```

Possible output:

```text
courses
students
teachers
```

### Showing Tables from a Specific Database

```sql
SHOW TABLES FROM school_db;
```

This is useful when you want to inspect a database without changing the selected database.

### Filtering Table Names

```sql
SHOW TABLES LIKE 'student%';
```

This displays tables whose names begin with `student`.

### Important Points

- `SHOW TABLES` lists table names, not table data.
- The database must be selected unless `FROM database_name` is used.
- A newly created database may contain no user tables.

---

## 7. `DESCRIBE`

The `DESCRIBE` command displays the structure of a table. Its short form is `DESC`.

### Syntax

```sql
DESCRIBE table_name;
```

or:

```sql
DESC table_name;
```

### Example

```sql
DESCRIBE students;
```

Typical output:

| Field | Type | Null | Key | Default | Extra |
|---|---|---|---|---|---|
| student_id | int | NO | PRI | NULL | |
| student_name | varchar(100) | NO | | NULL | |
| email | varchar(150) | YES | UNI | NULL | |
| age | int | YES | | NULL | |
| admission_date | date | YES | | NULL | |

### Meaning of the Output

- **Field:** Column name.
- **Type:** Data type and size.
- **Null:** Whether the column can contain `NULL`.
- **Key:** Key information, such as `PRI` for primary key or `UNI` for unique key.
- **Default:** Value automatically used if no value is supplied.
- **Extra:** Additional behavior, such as `auto_increment`.

### Viewing the Complete Table Definition

```sql
SHOW CREATE TABLE students;
```

This displays the SQL definition, including columns, constraints, indexes, storage engine, and character settings.

---

## 8. `DROP TABLE`

The `DROP TABLE` command permanently deletes a table and all its rows.

### Syntax

```sql
DROP TABLE table_name;
```

### Example

```sql
DROP TABLE students;
```

### Avoiding an Error if the Table Does Not Exist

```sql
DROP TABLE IF EXISTS students;
```

### Dropping Multiple Tables

```sql
DROP TABLE IF EXISTS students, teachers;
```

### Important Warning

`DROP TABLE` removes both:

- The table structure
- All data stored in the table

After dropping a table, commands such as `SELECT` and `DESCRIBE` cannot use it until it is created again.

### `DROP TABLE` vs `DELETE`

- `DROP TABLE` removes the table structure and its data.
- `DELETE` removes selected rows while keeping the table.
- `TRUNCATE TABLE` removes all rows while keeping the table structure.

---

## 9. `TRUNCATE TABLE`

The `TRUNCATE TABLE` command removes all rows from a table while keeping the table structure.

### Syntax

```sql
TRUNCATE TABLE table_name;
```

### Example

```sql
TRUNCATE TABLE students;
```

After this command:

- The `students` table still exists.
- The columns and constraints still exist.
- All records have been removed.
- The table is empty.

### `TRUNCATE TABLE` vs `DELETE`

| Feature | `TRUNCATE TABLE` | `DELETE` |
|---|---|---|
| Removes rows | All rows | Selected rows or all rows |
| Keeps table structure | Yes | Yes |
| Uses `WHERE` | No | Yes |
| Commonly faster for all rows | Yes | Usually slower for many rows |
| Can remove all data accidentally | Yes | Yes, if `WHERE` is omitted |
| Resets auto-increment behavior | Often resets it in MySQL | Usually does not reset it automatically |
| Fires row-level delete triggers | Behavior differs from `DELETE`; do not assume it does | Yes, where applicable |

### Important Warning

This is dangerous:

```sql
TRUNCATE TABLE students;
```

It removes every row. If only certain rows should be removed, use a carefully written `DELETE` statement with a `WHERE` clause.

## 10. `ALTER TABLE`

The `ALTER TABLE` command changes the structure of an existing table.

It can be used to:

- Add a column
- Modify a column
- Rename a column
- Drop a column
- Rename a table
- Add or remove constraints and indexes

### General Syntax

```sql
ALTER TABLE table_name action;
```

The action determines what change MySQL should make.

> **Warning:** Changing a column type or dropping a column can cause data loss. Review the table and take a backup before making structural changes to important data.

---

## 10.1 Add a Column

Use `ADD COLUMN` to add a new column to an existing table.

### Syntax

```sql
ALTER TABLE table_name
ADD COLUMN column_name data_type;
```

### Example

```sql
ALTER TABLE students
ADD COLUMN phone VARCHAR(20);
```

This adds a `phone` column to the `students` table.

### Adding a Column with a Default Value

```sql
ALTER TABLE students
ADD COLUMN status VARCHAR(20) DEFAULT 'active';
```

Rows created after the change use `active` when no status is supplied. Existing rows are handled according to the column definition and MySQL rules.

### Adding a Required Column to a Non-Empty Table

Adding a `NOT NULL` column to a table that already contains rows may require a default value or an update strategy:

```sql
ALTER TABLE students
ADD COLUMN country VARCHAR(50) NOT NULL DEFAULT 'Unknown';
```

### Adding a Column in a Specific Position

By default, a new column is added at the end. You can position it with `FIRST` or `AFTER`:

```sql
ALTER TABLE students
ADD COLUMN date_of_birth DATE AFTER student_name;
```

or:

```sql
ALTER TABLE students
ADD COLUMN notes TEXT FIRST;
```

Column order usually does not affect query results. Select columns explicitly when order matters:

```sql
SELECT student_id, student_name, phone
FROM students;
```

---

## 10.2 Modify a Column

Use `MODIFY COLUMN` to change a column's data type, size, default value, or nullability while keeping the same column name.

### Syntax

```sql
ALTER TABLE table_name
MODIFY COLUMN column_name new_definition;
```

### Example: Increase Text Length

```sql
ALTER TABLE students
MODIFY COLUMN student_name VARCHAR(150) NOT NULL;
```

This changes the maximum length of `student_name` from 100 to 150 characters.

### Example: Add a Default Value

```sql
ALTER TABLE students
MODIFY COLUMN status VARCHAR(20) NOT NULL DEFAULT 'active';
```

### Example: Change a Numeric Definition

```sql
ALTER TABLE courses
MODIFY COLUMN credits TINYINT NOT NULL DEFAULT 3;
```

### Important Points

- Include the complete desired column definition.
- Check whether existing values can be converted to the new type.
- Reducing a `VARCHAR` size may cause truncation or an error.
- Changing a nullable column to `NOT NULL` fails if existing rows contain `NULL` values.
- Test structural changes on a development database first.

---

## 10.3 Rename a Column

Use `RENAME COLUMN` to change a column's name while retaining its data type and values.

### Syntax

```sql
ALTER TABLE table_name
RENAME COLUMN old_name TO new_name;
```

### Example

```sql
ALTER TABLE students
RENAME COLUMN phone TO phone_number;
```

The column is now named `phone_number`.

### Checking the Result

```sql
DESCRIBE students;
```

### Compatibility Alternative

Some older MySQL versions or other database systems use `CHANGE COLUMN`, which requires the full definition:

```sql
ALTER TABLE students
CHANGE COLUMN phone phone_number VARCHAR(20);
```

With `CHANGE COLUMN`, provide the old name, new name, and complete new definition.

### Rename Caution

Renaming a column can break:

- Application queries
- Stored procedures
- Views
- Reports
- Triggers
- Scripts and scheduled jobs

Search dependent code before renaming a column in a production database.

---

## 10.4 Drop a Column

Use `DROP COLUMN` to permanently remove a column and its values.

### Syntax

```sql
ALTER TABLE table_name
DROP COLUMN column_name;
```

### Example

```sql
ALTER TABLE students
DROP COLUMN phone_number;
```

### Important Warning

Dropping a column removes all values in that column. The operation may also break applications, views, reports, or queries that depend on it.

Before dropping a column:

1. Check whether applications use it.
2. Check whether it is part of an index or constraint.
3. Back up the data if needed.
4. Confirm the correct table and column name.
5. Consider keeping the column temporarily if the change is part of a migration.

---

## 10.5 Rename a Table

Use `RENAME TABLE` to change a table's name.

### Syntax

```sql
RENAME TABLE old_table_name TO new_table_name;
```

### Example

```sql
RENAME TABLE students TO student_records;
```

The table is now named `student_records`.

### Alternative Syntax

MySQL also supports:

```sql
ALTER TABLE student_records
RENAME TO students;
```

### Renaming Multiple Tables

```sql
RENAME TABLE
    students TO student_records,
    teachers TO teacher_records;
```

### Rename Caution

A table rename can affect:

- SQL queries
- Application code
- Views and stored routines
- Reports
- Documentation
- Foreign key references and dependent objects

Check dependencies before renaming a table used by an application.

# Part 3: Complete Practice Example

The following script demonstrates database and table commands in a safe learning sequence.

```sql
-- Create a database
CREATE DATABASE IF NOT EXISTS school_db;

-- Select the database
USE school_db;

-- Create a students table
CREATE TABLE IF NOT EXISTS students (
    student_id INT PRIMARY KEY,
    student_name VARCHAR(100) NOT NULL,
    email VARCHAR(150) UNIQUE,
    age INT,
    admission_date DATE
);

-- List tables
SHOW TABLES;

-- Display the table structure
DESCRIBE students;

-- Add a column
ALTER TABLE students
ADD COLUMN phone VARCHAR(20);

-- Modify a column
ALTER TABLE students
MODIFY COLUMN student_name VARCHAR(150) NOT NULL;

-- Rename a column
ALTER TABLE students
RENAME COLUMN phone TO phone_number;

-- Display the changed structure
DESCRIBE students;

-- Rename the table
ALTER TABLE students
RENAME TO student_records;

-- List tables again
SHOW TABLES;

-- Display the new table structure
DESCRIBE student_records;
```

## Practice Cleanup Commands

Run these only when you no longer need the practice objects:

```sql
-- Remove all rows but keep the table
TRUNCATE TABLE student_records;

-- Remove the table completely
DROP TABLE IF EXISTS student_records;

-- Remove the database completely
DROP DATABASE IF EXISTS school_db;
```

Run cleanup commands one at a time and verify the object name before execution.

# Part 4: Command Comparison

## `DROP DATABASE` vs `DROP TABLE` vs `TRUNCATE TABLE`

| Command | Removes | Keeps structure? | Scope |
|---|---|---|---|
| `DROP DATABASE` | Database, tables, and data | No | Entire database |
| `DROP TABLE` | Table and its data | No | One or more tables |
| `TRUNCATE TABLE` | All rows | Yes | One table |
| `ALTER TABLE ... DROP COLUMN` | One column and its data | Table remains | One column |

## `DELETE` for Context

Although `DELETE` is not a main command in this module, it is useful for comparison:

```sql
DELETE FROM students
WHERE student_id = 10;
```

This removes only the matching record and keeps the table structure. Omitting `WHERE` removes every row:

```sql
DELETE FROM students;
```

Use caution with both `DELETE` and `TRUNCATE TABLE`.

# Part 5: Best Practices

- Use clear, descriptive database, table, and column names.
- Use `IF NOT EXISTS` and `IF EXISTS` when appropriate in repeatable scripts.
- Select the database with `USE` before working with tables.
- Run `SHOW DATABASES`, `SHOW TABLES`, and `DESCRIBE` to confirm the current structure.
- Use explicit column lists in queries instead of depending on column order.
- Back up important data before using `DROP`, `TRUNCATE`, or structural changes.
- Test `ALTER TABLE` statements in a development environment first.
- Do not drop a column or table without checking application dependencies.
- Keep database change scripts under version control.
- Use an account with only the privileges required for the task.
- Use transactions where appropriate, but remember that some structural commands may cause implicit commits in MySQL.

# Part 6: Common Beginner Errors

## Error: No Database Selected

**Cause:** A table command was executed without selecting a database.

**Solution:**

```sql
USE school_db;
```

## Error: Table Already Exists

**Cause:** A table with the same name already exists.

**Solution:** Inspect it first:

```sql
SHOW TABLES;
DESCRIBE students;
```

If it is only a practice table, use:

```sql
DROP TABLE IF EXISTS students;
```

Then create it again.

## Error: Unknown Table

**Cause:** The table name is misspelled, the wrong database is selected, or the table has not been created.

**Solution:**

```sql
SELECT DATABASE();
SHOW TABLES;
```

## Error: Unknown Column

**Cause:** A query refers to a column that does not exist or has been renamed.

**Solution:**

```sql
DESCRIBE table_name;
```

Check the exact column name.

## Error: Cannot Add a Required Column

**Cause:** A `NOT NULL` column was added to a table containing rows without a suitable default value.

**Solution:** Add a default value or add the column as nullable, update existing rows, and then apply `NOT NULL`.

## Error: Data Truncated or Incorrect Value

**Cause:** Existing data cannot be safely converted to the new column type or size.

**Solution:** Inspect and clean the existing values before using `MODIFY COLUMN`.
