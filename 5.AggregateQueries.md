# Aggregate Queries

Aggregate functions perform calculations on multiple rows and return a single result. They are useful for finding totals, averages, counts, and extreme values.

The examples below use the `students` table:

```text
students(student_id, first_name, last_name, email, phone, marks, rank)
```

## `COUNT`

`COUNT` counts rows or non-`NULL` values.

### Count All Students

```sql
SELECT COUNT(*) AS total_students
FROM students;
```

`COUNT(*)` counts every row, including rows where some column values are `NULL`.

### Count Values in a Column

```sql
SELECT COUNT(phone) AS students_with_phone
FROM students;
```

`COUNT(phone)` counts only rows where `phone` is not `NULL`.

### Count Distinct Values

```sql
SELECT COUNT(DISTINCT last_name) AS distinct_last_names
FROM students;
```

`DISTINCT` ensures that repeated values are counted only once.

## `SUM`

`SUM` calculates the total of numeric values:

```sql
SELECT SUM(marks) AS total_marks
FROM students;
```

To calculate the total marks of students who scored at least 50:

```sql
SELECT SUM(marks) AS passing_marks_total
FROM students
WHERE marks >= 50;
```

## `AVG`

`AVG` calculates the average of numeric values:

```sql
SELECT AVG(marks) AS average_marks
FROM students;
```

Values that are `NULL` are ignored by `AVG`.

You can round the result using `ROUND`:

```sql
SELECT ROUND(AVG(marks), 2) AS average_marks
FROM students;
```

## `MIN`

`MIN` returns the smallest value:

```sql
SELECT MIN(marks) AS lowest_marks
FROM students;
```

It can also be used with text or other comparable values:

```sql
SELECT MIN(first_name) AS first_name_in_order
FROM students;
```

## `MAX`

`MAX` returns the largest value:

```sql
SELECT MAX(marks) AS highest_marks
FROM students;
```

To find the highest rank number:

```sql
SELECT MAX(`rank`) AS highest_rank_number
FROM students;
```

## Using Multiple Aggregate Functions

Several aggregate functions can be used in one query:

```sql
SELECT
    COUNT(*) AS total_students,
    SUM(marks) AS total_marks,
    ROUND(AVG(marks), 2) AS average_marks,
    MIN(marks) AS lowest_marks,
    MAX(marks) AS highest_marks
FROM students;
```

## `GROUP BY`

`GROUP BY` divides rows into groups before applying aggregate functions. For example, group students by their rank:

```sql
SELECT
    `rank`,
    COUNT(*) AS students_in_rank
FROM students
GROUP BY `rank`;
```

Although rank is normally unique in a well-defined ranking system, this example shows how grouping works when multiple rows share the same value.

You can group by more than one column:

```sql
SELECT
    last_name,
    COUNT(*) AS student_count,
    ROUND(AVG(marks), 2) AS average_marks
FROM students
GROUP BY last_name;
```

## `HAVING`

`HAVING` filters groups after aggregation. Use `WHERE` to filter individual rows before grouping and `HAVING` to filter grouped results.

```sql
SELECT
    last_name,
    COUNT(*) AS student_count,
    ROUND(AVG(marks), 2) AS average_marks
FROM students
GROUP BY last_name
HAVING COUNT(*) > 1;
```

This returns only last names shared by more than one student.

## Aggregate Queries with `ORDER BY` and `LIMIT`

You can sort grouped results and return only a limited number of groups:

```sql
SELECT
    last_name,
    ROUND(AVG(marks), 2) AS average_marks
FROM students
GROUP BY last_name
ORDER BY average_marks DESC
LIMIT 5;
```

This returns the five last-name groups with the highest average marks.

## Aggregate Query Order

When these clauses are used together, write them in this order:

```sql
SELECT grouping_columns, aggregate_function(column)
FROM table_name
WHERE row_condition
GROUP BY grouping_columns
HAVING group_condition
ORDER BY column_name
LIMIT number;
```

For example:

```sql
SELECT
    last_name,
    COUNT(*) AS student_count,
    ROUND(AVG(marks), 2) AS average_marks
FROM students
WHERE marks IS NOT NULL
GROUP BY last_name
HAVING AVG(marks) >= 60
ORDER BY average_marks DESC
LIMIT 10;
```

## Important Points

- Aggregate functions usually ignore `NULL` values, except `COUNT(*)`, which counts rows.
- `WHERE` filters rows before aggregation.
- `GROUP BY` creates groups for aggregate calculations.
- `HAVING` filters groups after aggregation.
- Use column aliases such as `average_marks` to make results easier to understand.

## Cardinality and Relationships

**Cardinality** describes how many instances of one entity can be associated with instances of another entity. It is used to describe the number of relationships between two groups of objects.

For example, cardinality helps answer questions such as:

- Can one person have one passport or many passports?
- Can one employee manage many employees?
- Can one user place many orders?
- Can one student enroll in many courses?

The three common types of cardinality are:

- One-to-one
- One-to-many
- Many-to-many

### One-to-One Relationship

In a **one-to-one** relationship, one instance of the first entity is associated with one instance of the second entity, and vice versa.

#### Example: Person and Passport

One person has one passport, and each passport belongs to one person:

```text
Person A  ───────────  Passport A
Person B  ───────────  Passport B
```

Another example is an employee and the employee ID card assigned to that employee:

```text
Employee A  ───────────  ID Card A
Employee B  ───────────  ID Card B
```

The relationship can be described as **1:1**.

### One-to-Many Relationship

In a **one-to-many** relationship, one instance of the first entity can be associated with many instances of the second entity. Each instance on the many side is associated with one instance on the one side.

#### Example: Manager and Employees

One manager can manage many employees, but each employee reports to one manager:

```text
                 ┌── Employee A
Manager A ───────┼── Employee B
                 └── Employee C
```

Another example is a user and their orders:

```text
              ┌── Order 1
User A ───────┼── Order 2
              └── Order 3
```

The relationship can be described as **1:N**, where `N` means many.

### Many-to-Many Relationship

In a **many-to-many** relationship, many instances of the first entity can be associated with many instances of the second entity.

#### Example: Students and Courses

- One student can enroll in many courses.
- One course can have many students.

```text
Student A ─────── Course 1
         ├─────── Course 2
Student B ─────── Course 1
         └─────── Course 3
```

Both students can enroll in multiple courses, and each course can have multiple students.

Another example is users and products in an online shopping system:

```text
User A ─────── Product X
      ├─────── Product Y
User B ─────── Product X
      └─────── Product Z
```

The relationship can be described as **M:N**, where both sides can have many instances.

### Cardinality Comparison

| Cardinality | Meaning | Example |
|---|---|---|
| One-to-one (1:1) | One instance is related to one instance | Person and passport |
| One-to-many (1:N) | One instance is related to many instances | Manager and employees |
| Many-to-many (M:N) | Many instances are related to many instances | Users and orders or students and courses |

Cardinality describes the relationship between entities; it does not describe the number of columns, the size of an object, or the importance of an entity.

## Connecting Students and Departments

Suppose our college also has a `departments` table with the following columns:

- `department_id`: A unique identifier for each department
- `name`: The department name
- `hod`: The name of the head of the department

Create the table using:

```sql
CREATE TABLE departments (
    department_id INT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    hod VARCHAR(100) NOT NULL
);
```

### How Can We Connect the Two Tables?

We have two tables:

```text
students(student_id, first_name, last_name, department_id)
departments(department_id, name, hod)
```

How can we show which department each student belongs to?

### Understanding the Cardinality

The relationship between `departments` and `students` is **one-to-many**:

- One department can have many students.
- Each student belongs to one department.

The relationship can be represented as:

```text
Department 1 ─────── Student 1
             ├────── Student 2
             └────── Student 3
```

Therefore, `department_id` should be stored in the `students` table. It identifies the department to which each student belongs.

### Adding `department_id` to `students`

If the `students` table already exists, add the new column:

```sql
ALTER TABLE students
ADD COLUMN department_id INT;
```

Then establish the relationship by adding a foreign key:

```sql
ALTER TABLE students
ADD CONSTRAINT fk_students_department
FOREIGN KEY (department_id)
REFERENCES departments(department_id);
```

The foreign key ensures that a `department_id` entered in `students` must exist in `departments`.

After adding the relationship, a student can be assigned to a department:

```sql
UPDATE students
SET department_id = 10
WHERE student_id = 101;
```

The department with `department_id = 10` must already exist before this update succeeds.
