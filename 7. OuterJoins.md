# Outer Joins in SQL

An **outer join** returns matching rows and can also preserve unmatched rows from one or both tables.

Assume these tables:

```text
students(student_id, first_name, last_name, marks, rank, age, department_id)
departments(department_id, name, hod)
```

The tables are related through `department_id`.

Example:

### `students`

| student_id | first_name | department_id |
|---:|---|---:|
| 101 | Asha | 10 |
| 102 | Ravi | 20 |
| 103 | Meera | 10 |
| 104 | Arjun | 30 |
| 105 | Neha | 50 |

### `departments`

| department_id | name |
|---:|---|
| 10 | Computer Science |
| 20 | Physics |
| 30 | Mathematics |
| 40 | Chemistry |

Here, department `40` has no students, and student `105` has no matching department.

## `LEFT JOIN`

A `LEFT JOIN` returns every row from the left table and matching rows from the right table. If no matching row exists in the right table, the right-table columns contain `NULL`.

```sql
SELECT
    s.student_id,
    s.first_name,
    d.name AS department_name
FROM students AS s
LEFT JOIN departments AS d
    ON s.department_id = d.department_id;
```

Because `students` is on the left, every student appears. Student `105` also appears, but `department_name` is `NULL` because department `50` does not exist.

### Finding Students Without a Department

```sql
SELECT
    s.student_id,
    s.first_name,
    s.department_id
FROM students AS s
LEFT JOIN departments AS d
    ON s.department_id = d.department_id
WHERE d.department_id IS NULL;
```

The `NULL` check finds students whose department does not have a matching record.

### Finding Departments and Their Student Counts

To include departments that have no students, put `departments` on the left:

```sql
SELECT
    d.name AS department_name,
    COUNT(s.student_id) AS student_count
FROM departments AS d
LEFT JOIN students AS s
    ON d.department_id = s.department_id
GROUP BY d.department_id, d.name
ORDER BY d.name;
```

Department `Chemistry` appears with a count of `0`.

## `RIGHT JOIN`

A `RIGHT JOIN` returns every row from the right table and matching rows from the left table. If no matching row exists in the left table, the left-table columns contain `NULL`.

```sql
SELECT
    s.student_id,
    s.first_name,
    d.name AS department_name
FROM students AS s
RIGHT JOIN departments AS d
    ON s.department_id = d.department_id;
```

Because `departments` is on the right, every department appears. Department `40` appears even though it has no students.

The same result can usually be written more clearly with a `LEFT JOIN` by placing the table that must be preserved on the left:

```sql
SELECT
    s.student_id,
    s.first_name,
    d.name AS department_name
FROM departments AS d
LEFT JOIN students AS s
    ON d.department_id = s.department_id;
```

## `FULL OUTER JOIN`

A `FULL OUTER JOIN` returns:

- Every matching row
- Every unmatched row from the left table
- Every unmatched row from the right table

```sql
SELECT
    s.student_id,
    s.first_name,
    d.department_id,
    d.name AS department_name
FROM students AS s
FULL OUTER JOIN departments AS d
    ON s.department_id = d.department_id;
```

The result includes all students and all departments. Student `105` appears with `NULL` department details, and department `40` appears with `NULL` student details.

### Simulating `FULL OUTER JOIN` in MySQL

MySQL does not support the `FULL OUTER JOIN` syntax directly. It can be simulated by combining a `LEFT JOIN` and a `RIGHT JOIN` with `UNION`:

```sql
SELECT
    s.student_id,
    s.first_name,
    d.department_id,
    d.name AS department_name
FROM students AS s
LEFT JOIN departments AS d
    ON s.department_id = d.department_id

UNION

SELECT
    s.student_id,
    s.first_name,
    d.department_id,
    d.name AS department_name
FROM students AS s
RIGHT JOIN departments AS d
    ON s.department_id = d.department_id;
```

`UNION` removes duplicate matching rows. Use `UNION ALL` only when duplicate rows are intentionally required.

## Outer Join Comparison

| Join type | Rows preserved |
|---|---|
| `LEFT JOIN` | All rows from the left table |
| `RIGHT JOIN` | All rows from the right table |
| `FULL OUTER JOIN` | All rows from both tables |

The choice of outer join depends on which unmatched records must remain in the result.

## More Outer-Join Examples

### Including Student Marks

Use a `LEFT JOIN` when every student must appear, even if the student has no matching department:

```sql
SELECT
    s.student_id,
    s.first_name,
    s.marks,
    d.name AS department_name
FROM students AS s
LEFT JOIN departments AS d
    ON s.department_id = d.department_id
ORDER BY s.marks DESC;
```

Student `105` remains in the result with a `NULL` department name.

### Departments with Students Above a Marks Threshold

This query keeps every department while counting only students who scored at least 80:

```sql
SELECT
    d.name AS department_name,
    COUNT(s.student_id) AS high_scorer_count
FROM departments AS d
LEFT JOIN students AS s
    ON d.department_id = s.department_id
   AND s.marks >= 80
GROUP BY d.department_id, d.name
ORDER BY high_scorer_count DESC;
```

The condition is placed in the `ON` clause so that departments with no high-scoring students are still included with a count of `0`.

### Departments Without High Scorers

```sql
SELECT
    d.department_id,
    d.name
FROM departments AS d
LEFT JOIN students AS s
    ON d.department_id = s.department_id
   AND s.marks >= 80
WHERE s.student_id IS NULL;
```

This returns departments that have no student with marks of at least 80.

### Important Difference Between `ON` and `WHERE`

To preserve unmatched departments, put the student condition in `ON`:

```sql
SELECT
    d.name AS department_name,
    s.first_name,
    s.marks
FROM departments AS d
LEFT JOIN students AS s
    ON d.department_id = s.department_id
   AND s.marks >= 80;
```

If the same condition is placed in `WHERE`, departments without a matching student are removed:

```sql
SELECT
    d.name AS department_name,
    s.first_name,
    s.marks
FROM departments AS d
LEFT JOIN students AS s
    ON d.department_id = s.department_id
WHERE s.marks >= 80;
```

The second query behaves like an inner join for this condition because rows with `NULL` marks fail the `WHERE` condition.

### Right Join with Department Heads

Use a `RIGHT JOIN` to keep every department while displaying matching students and the head of the department:

```sql
SELECT
    d.name AS department_name,
    d.hod,
    s.first_name AS student_name
FROM students AS s
RIGHT JOIN departments AS d
    ON s.department_id = d.department_id
ORDER BY d.name, s.first_name;
```

Departments with no students still appear, with `NULL` in `student_name`.

### Finding All Unmatched Records

In a database that supports `FULL OUTER JOIN`, use it to find records that exist on only one side:

```sql
SELECT
    s.student_id,
    s.first_name,
    d.department_id,
    d.name AS department_name
FROM students AS s
FULL OUTER JOIN departments AS d
    ON s.department_id = d.department_id
WHERE s.student_id IS NULL
   OR d.department_id IS NULL;
```

This returns students without departments and departments without students.

### Full-Join Workaround for Unmatched Records in MySQL

MySQL can find unmatched records with two anti-join queries:

```sql
SELECT
    s.student_id,
    s.first_name,
    NULL AS department_id,
    NULL AS department_name
FROM students AS s
LEFT JOIN departments AS d
    ON s.department_id = d.department_id
WHERE d.department_id IS NULL

UNION ALL

SELECT
    NULL AS student_id,
    NULL AS first_name,
    d.department_id,
    d.name AS department_name
FROM departments AS d
LEFT JOIN students AS s
    ON d.department_id = s.department_id
WHERE s.student_id IS NULL;
```

The first query finds unmatched students, and the second finds unmatched departments.
