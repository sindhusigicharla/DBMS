# Keys in a Relational Database

Keys are columns, or combinations of columns, used to identify rows and establish relationships between tables.

Consider the following `students` table:

| student_id | roll_number | email | name |
|---:|---:|---|---|
| 101 | 1 | asha@example.com | Asha |
| 102 | 2 | ravi@example.com | Ravi |

Assume that `student_id`, `roll_number`, and `email` are each unique for every student.

## Super Key

A **super key** is any column or combination of columns that can uniquely identify a row in a table.

In the `students` table, the following are super keys:

- `{student_id}`
- `{roll_number}`
- `{email}`
- `{student_id, name}`
- `{roll_number, email}`

The last two combinations are super keys because they uniquely identify a student, even though they contain more columns than necessary.

A super key may contain extra attributes. For example, `student_id` alone is enough to identify a student, so `{student_id, name}` is a super key with an unnecessary column.

## Candidate Key

A **candidate key** is a minimal super key. It uniquely identifies a row, and no column can be removed from it without losing that uniqueness.

In the example, these are candidate keys:

- `student_id`
- `roll_number`
- `email`

`{student_id, name}` is not a candidate key because `student_id` alone already identifies the row. Similarly, `{roll_number, email}` is not minimal because either column is sufficient by itself.

### Properties of a Candidate Key

- It uniquely identifies every row.
- It contains no unnecessary column.
- A table can have more than one candidate key.
- A candidate key may consist of one column or multiple columns.
- Candidate-key columns cannot contain duplicate values.
- Candidate-key columns generally cannot be `NULL`, because a missing value cannot reliably identify a row.

When a candidate key contains multiple columns, it is called a **composite candidate key**. For example, in an `enrollments` table, the combination `{student_id, course_id}` may identify one enrollment:

| student_id | course_id | semester |
|---:|---:|---|
| 101 | 501 | Spring |
| 101 | 502 | Spring |

Here, `student_id` alone is not unique and `course_id` alone is not unique, but their combination can be unique.

## Super Key vs Candidate Key

| Super Key | Candidate Key |
|---|---|
| Any column or column combination that uniquely identifies a row | A minimal super key |
| May contain unnecessary columns | Contains no unnecessary columns |
| A table can have many super keys | A table can have one or more candidate keys |
| Example: `{student_id, name}` | Example: `{student_id}` |

Every candidate key is a super key, but every super key is not a candidate key.

## Primary Key

A **primary key** is the candidate key selected to be the main identifier for rows in a table.

For the `students` table, we may choose `student_id` as the primary key:

```sql
CREATE TABLE students (
    student_id INT PRIMARY KEY,
    roll_number INT UNIQUE NOT NULL,
    email VARCHAR(255) UNIQUE NOT NULL,
    name VARCHAR(100) NOT NULL
);
```

The other candidate keys, such as `roll_number` and `email`, become **alternate keys** after `student_id` is selected as the primary key.

## Why Do We Need a Primary Key?

### 1. To Uniquely Identify Rows

A primary key ensures that every row represents one distinct record. Two students cannot have the same `student_id`.

### 2. To Prevent Duplicate Records

The database prevents two rows from having the same primary-key value.

### 3. To Create Relationships Between Tables

Other tables can refer to the primary key using a **foreign key**:

```sql
CREATE TABLE enrollments (
    student_id INT,
    course_id INT,
    FOREIGN KEY (student_id) REFERENCES students(student_id)
);
```

This connects each enrollment to a valid student.

### 4. To Update or Delete the Correct Row

A primary key allows an application to identify exactly which row should be changed:

```sql
UPDATE students
SET name = 'Asha Sharma'
WHERE student_id = 101;
```

### 5. To Improve Data Access

RDBMSs usually create an index for a primary key. This helps the database locate rows efficiently.

### 6. To Maintain Data Integrity

A primary key cannot contain duplicate or `NULL` values. This ensures that every stored row has a reliable identity.
